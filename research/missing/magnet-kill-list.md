# Magnet kill list — candidates evaluated and rejected (with reasons)

Per the adversarial mandate: weak ideas are killed explicitly, with the reasoning on record so they are not re-pitched next quarter without new evidence.

## KILL — Elpriskoll / effekttariff-verktyget
The candidate: a live electricity-price / effekttariff-checker ("vad kostar din el just nu / vad gör effekttariffen med din faktura").
1. **Wrong lane.** Effekttariff economics is battery-sale fuel — commercial priority #3, OFF Google Ads by owner decision. Building distribution for the lowest-priority lane while the #1 lane (service) just got its first magnet (foto-bedömning) inverts the owner's own priority, again — the exact HP-01/CAT-13 inversion pattern this audit keeps finding, reproduced in the magnet portfolio.
2. **No white-space.** Elpris-checking is a commodity owned by dedicated apps/sites and every elhandelsbolag; Ampy cannot win that query class, and a me-too widget earns neither links nor trust. The existing Energikalkylatorn + Batterikalkylatorn already encode elområde/förbrukning/effekt where it actually feeds a Ampy decision.
3. **Maintenance liability.** Live price data means feeds, breakage, and stale-data candour risk (a wrong live price on a candour-brand site is worse than no widget). The magnet family's current problem is that even STATIC plumbing (webhooks, phone numbers) is unverified — adding a data-feed dependency is the last thing the portfolio needs.
4. **No conversion path.** "Elpriset är högt" routes to... an elhandel switch, not an electrician. The JTBD dead-ends outside Ampy's two conversions.
**Reopening condition:** none foreseeable within this 3–6 month program. If batteries return to paid focus with owner-confirmed effekttariff facts, revisit as a section INSIDE Batterikalkylatorn, not a standalone tool.

## KILL (as a category) — any NEW calculator before the wiring debt is paid
The portfolio audit's meta-finding: **7 magnets, 0 verified lead pipelines** (energikalkylator webhook recorded as a stub; a dead placeholder phone number in the batterikalkylator failure state; no form_start events anywhere; 5 of 7 pages without a trust close; 3 tools absent from all navigation). The constraint is not inventory — it is wrap, wiring, and distribution. Any proposal for "kalkylator #8" (spotlight-kalkylator, golvvärme-kalkylator, solcells-ROI…) is auto-deferred until: LM-01 + LM-02 verified, the wrap standard live on energi + laddbox, and the Verktygs-tile shipping traffic into the existing tools. Exception granted only to foto-bedömning (it is a form-offer, not a calculator, and it is the sole service-lane asset) and the BRF-guide (content asset, phase 2).

## KILL — email-gated PDF as the default magnet format
Evaluated inside magnet-offert-checklista.md: gating trust artifacts inverts their psychology for this audience, and no nurture pipeline exists to work cold emails today. The single sanctioned soft gate is the BRF-guide's forwardable PDF (org context makes the trade fair, and the on-page version stays ungated). Everything else in the family stays value-then-ask, results-before-any-fields.
